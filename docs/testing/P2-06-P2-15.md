## Diseño y principios FIRST

- **Fast:** Mockito simula repositorios y AttendeeGuard en las pruebas de SurveyService. No hay PostgreSQL, HTTP ni Gemini reales.
- **Isolated:** MockitoExtension crea mocks para cada ejecución; BeforeEach prepara entidades nuevas. No se comparte estado mutable entre pruebas.
- **Repeatable:** datos fijos; sin reloj, aleatoriedad, esperas ni dependencias del entorno en estas nuevas pruebas.
- **Self-Validating:** aserciones de datos capturados, identidad de objetos y excepciones; verificaciones de ausencia de persistencia y orden del control de asistencia.
- **Timely:** pruebas incorporadas durante el sprint al revisar ramas sin cubrir; no se afirma que se crearon antes del código existente.

Se prueban escenarios válidos, ausentes, duplicados y fallos de dependencias.
La parametrización distingue dos clases de error. Son técnicas de diseño del
equipo; el material del docente presenta FIRST, fixtures, aserciones y mocks.

## Reproducción

Desde `backend/`, con JDK 21 seleccionado:

```bash
mvn -B -ntp clean verify
```

En macOS se puede seleccionar el JDK con
`export JAVA_HOME=$(/usr/libexec/java_home -v 21)` y verificar con `mvn -version`.
